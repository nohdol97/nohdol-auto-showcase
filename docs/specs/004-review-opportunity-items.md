# 스펙 004: 당근 공개 후기에서 프로그램 아이템 발굴

- 상태: active
- 날짜: 2026-09-06
- 관련 ADR: [003](../adr/003-review-evidence-boundary.md)

## 문제와 목표

주변 업체 정보만으로는 실제 고객 경험에 연결된 프로그램 아이템을 제안하기 어렵다. 운영자가 당근 업체 링크를 입력하면 서버가 초기 공개 페이지에 포함된 고객 후기와 사장님 답글을 구분하고, 근거 요약 → 업무 가설 → 확인 질문 → 작은 데모와 검증 지표를 제안한다.

## 비목표

Google·네이버·카카오 후기 수집, 로그인·차단 우회, 후기 전체 수집, 페이지 추가 탐색, 자동 연락, 구매 수요 단정, 원문·작성자 프로필의 장기 저장 및 기존 주변 업체 검색의 대체는 포함하지 않는다. Google은 실제 연결과 데이터 이용 범위가 검증된 후 별도 연결한다. 운영 배포는 2026-09-07 사용자의 별도 요청으로 승인되었다.

## 요구사항과 완료 기준

### R1. 인증된 링크 실행

`POST /api/admin/radar/review-runs`는 기존 관리자 세션과 same-origin 검사를 사용한다. HTTPS `www.daangn.com/kr/local-profile/<slug>-<id>/`만 허용하고 추적 쿼리·프래그먼트는 제거한다. 자격증명·다른 호스트·포트·인코딩 경로 우회는 거부한다. 주변 검색 설정이나 Kakao 키 없이 OpenAI·D1·Queue로 실행할 수 있다. 최대 한 실행만 활성화한다.

검증: 인증·잘못된 URL·설정 없는 실행·중복 실행 API 회귀.

### R2. 지속 실행과 최소 데이터

HTTP는 URL과 `daangn:<id>` 식별자만 포함하는 업체 작업을 Queue에 넣고 202로 반환한다. 소비자에서 요청을 실행한다. 기존 멱등 저장·세 번 제한 재시도·정체 복구·1년 실행 보관을 재사용한다. URL 실행은 수동 실행이며 기존 매일 주변 검색 설정을 변경하지 않는다. D1 열 `kakao_id`는 기존 호환성을 위해 유지하되 당근 식별자는 접두어로 분리한다.

검증: Queue에 원문·작성자 데이터 없음, 소비자 완료·중복 전달·실패 저장.

### R3. 제한된 공개 페이지 수집

서버는 허용된 URL에 쿠키·인증 없이 요청하며 리다이렉트를 따라가지 않는다. 15초 및 2 MiB 응답 제한을 적용한다. 403·429·기타 오류는 사용자에게 구분해서 알리고 우회하지 않는다. HTML 내 `window.__remixContext` JSON의 알려진 업체 경로에서 업체 필드와 `reviews[].content`, `reviews[].comment.content`만 읽는다. 코드를 실행하지 않는다. JSON-LD 후기 필드는 역할 판정 근거로 사용하지 않는다. 최대 10개 고객 후기와 10개 답글, 각 600자만 분석 입력에 전달하고 작성자·프로필·이미지·원본 HTML을 제외한다. 이메일·전화·URL 등 본문 연락 정보는 제거한다. 구조가 달라지면 수집 실패로 표시한다.

검증: 합성 fixture로 고객/답글 구분, JSON-LD 오표기, 중복·빈 후기, 개인정보 최소화, 스크립트 미실행, 용량·시간·리다이렉트·403·429 실패.

### R4. 근거에 연결된 아이템

실제 수집한 고객 후기가 없으면 아이템을 생성하지 않는다. 원문과 답글은 신뢰할 수 없는 모델 입력이다. 고객 주장을 업체의 확정 사실로 쓰지 않으며 긍정적 경험을 문제나 구매 의사로 바꾸지 않는다. 각 업무 신호는 수집한 근거 ID와 역할을 참조하고, 각 아이템은 최소 한 고객 후기의 신호를 포함한다. 1~3개 아이템은 근거 ID·업무 가설·첫 질문·작은 데모·검증 지표를 포함한다. 서버는 존재하지 않거나 역할이 다른 참조를 거부한다. 후기 기반 신뢰도는 최대 60, 고객 후기 1개일 때 최대 30으로 제한한다. 기존 prototypeOffer는 첫 추천의 상세 제안으로 유지한다.

검증: 분석 입력 경계, 가짜 근거·역할 불일치 거부, 신뢰도 제한, 아이템 필수 필드.

### R5. 저장과 표시

저장 결과에는 모델이 요약한 신호와 아이템, 정규화 출처 URL, 확인 시각, 초기 HTML에서 읽은 고객 후기 수·답글 수·전체 표시 수(있을 때), 초기 페이지 일부 수집이라는 범위를 포함한다. 원문·작성자 정보는 저장하지 않는다. 모델 출력에서 공백·구두점 정규화 후 24자 이상 연속된 원문 복제를 검출하면 저장을 거부한다. 짧은 일반 표현의 겹침까지 금지하지는 않는다. 모델이 반환한 후기 출처는 실제 서버 수집 URL과 일치해야 한다. 기존 분석 결과도 그대로 표시된다. 실패는 원문이나 내부 오류 대신 정해진 복구 메시지로 알린다.

검증: D1 저장 payload, 상태 응답, 기존 결과 표시, 실제 수집 수와 전체 수 구분, DOM textContent 사용.

### R6. 관리자 UX와 회귀

관리자는 링크 입력 → 발굴 → 진행 상태 → 근거·추천 아이템을 한 흐름으로 확인한다. 입력 오류와 실행 실패 후 링크가 보존되고 재시도할 수 있다. 주변 업체 검색과 후기 실행의 준비 상태를 분리한다. 실행 중 중복 제출을 막는다. Google·네이버 후기를 수집한 것처럼 표시하지 않는다.

표면: responsive showcase 관리자 화면. 기존 흑백 토큰·로고·44px 조작 영역·키보드 포커스 유지. 390/768/1440px에서 빈 결과·성공·실패·진행·긴 한국어와 overflow를 검증한다.

검증: API·UI 회귀, `npm run verify`, Abalone 정적 audit, 합성 결과를 사용하는 Chromium 시나리오.

## 이행과 되돌리기

DB 마이그레이션과 새 비밀값은 없다. 기존 API와 Queue 작업을 계속 수용한다. 되돌릴 때 진행 중인 후기 Queue 작업을 먼저 마치거나 실패 상태로 정리한 뒤 이전 버전을 배포한다. 소스 push와 실제 배포는 별도 증거이며 이번 구현만으로 운영 반영을 주장하지 않는다.

## 검증 범위

- R1~R6: 73개 프로젝트 회귀와 빌드·Worker dry-run, 관리자 390/768/1440px 합성 Chromium 검증 통과.
- R2: 기존 마이그레이션의 메모리 SQLite에 실제 SQL을 실행하여 단일 활성 실행·최종 실패 저장·상태 조회·재시작을 확인했다.
- R3: 일반 HTTP 수집 표본에서 고객 후기 8개·사장님 답글 5개·표시 전체 11개를 확인했다. 이는 한 업체의 초기 페이지 표본이며 모든 업체의 수집 안정성을 입증하지 않는다.
- 모델 요청 형식: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)와 기존 Responses 구현을 대조했다. 아래 운영 표본은 당근 수집 단계에서 차단되어 실제 후기 모델 응답과 품질은 미검증이다.
- 2026-09-07 사용자 요청으로 소스 `116c35e`를 Worker 버전 `aed7f0ef-bf49-452c-bce0-66745cbc7d0b`에 배포했다. `wrangler deployments status --json`으로 해당 버전의 운영 트래픽 100%를 확인했다. DB 마이그레이션과 비밀값 변경은 없었다.
- 운영 HTML·JS·CSS는 `_site` SHA-256과 일치하고 `no-store`·`noindex`를 반환했다. 미인증 후기 실행은 401, Chromium 390/1440px 로그인 화면은 가로 넘침·페이지 오류 없이 표시됐다. `/api/health`는 `ready`, 홈·앱 상세·설치 안내는 HTTP 200이었다.
- 실제 인증 실행 `fcdfc1a0-7864-4658-a316-d453ff911583`은 202 접수 후 Queue의 제한 재시도를 거쳐 `failed · 0/1`로 종료됐다. 운영 Worker의 당근 접근 차단이 원인이며 상태 API에 정해진 차단 안내와 출처 링크가 보존됐다. 이는 실패 처리 검증이며 후기 수집·아이템 생성 성공을 뜻하지 않는다. 일반 HTTP 표본의 성공을 운영 환경 성공으로 확대하지 않는다.
- 되돌리기 기준 버전은 `3221d948-a554-4c76-8513-e9a30e52a444`이다. 합성 화면 결과를 실제 업체의 분석 결과로 취급하지 않는다.
- 후속 [Cloudflare 헤드리스 진단](../proposals/001-daangn-cloudflare-headless.md)에서는 같은 업체를 HTTP 200으로 읽고 고객 후기 8개·답글 5개를 파싱했다. 별도 진단 Worker 결과이며 운영 Radar의 수집 방식 변경이나 실제 모델 분석 성공을 의미하지 않는다.
