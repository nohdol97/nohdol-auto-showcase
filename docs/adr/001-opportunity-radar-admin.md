# ADR 001: 공개 사이트 Worker에 분리된 기회 Radar 관리자 경계 추가

- 날짜: 2026-09-05
- 상태: accepted

## 배경

기존 Abalone Radar는 로컬 프로토타입이라 사용자가 직접 실행하고 관찰해야 한다. 공개 쇼케이스 Worker는 이미 동일 출처 정적 자산, D1, OpenAI Responses API, 예약 실행을 운영하지만, 제품키·설치 배포 관리자 권한은 의도적으로 소유하지 않는다. 가까운 업체의 공개 근거를 매일 정리하는 내부 영업 조사 화면은 필요하지만 배포 관리자 경계와 섞이면 안 된다.

## 결정

`nohdol-auto-showcase`에 `/admin/radar/` 정적 화면과 `/api/admin/radar/*` API를 추가한다. 이 경계는 공개 장소 검색과 내부 기회 조사만 소유하며 설치 코드, 제품키, 비공개 설치 파일, 배포 상태를 읽거나 변경할 수 없다.

인증은 `RADAR_ADMIN_PASSWORD` 하나로 서명한 짧은 수명의 same-origin 쿠키를 사용한다. 비밀번호는 Worker secret 또는 로컬 `.dev.vars`에만 존재하고 정적 빌드에는 포함하지 않는다. 조사 설정·실행·요약 근거는 기존 D1의 별도 `radar_*` 테이블에 저장한다. Kakao 검색과 OpenAI 웹 검색은 서버에서만 실행한다.

## 대안

- 로컬 Radar만 확장: 비밀 관리가 단순하지만 매일 자동 실행과 어디서든 접근이 어렵다.
- 별도 Radar Worker와 데이터베이스: 권한 분리는 더 강하지만 현재 규모에서 배포·운영 지점과 비용이 불필요하게 늘어난다.
- 설치 배포 관리자에 통합: 이미 강한 관리자 인증이 있지만 기회 조사와 제품 배포의 권한·데이터 수명이 달라 결합을 거부한다.

## 결과

- 한 사이트에서 내부 Radar에 접근하고 기존 예약 실행과 모델 구성을 재사용할 수 있다.
- 단일 공유 비밀번호이므로 다중 사용자 감사·철회는 제공하지 않는다. 비밀번호 교체가 기존 세션을 즉시 무효화한다.
- 쇼케이스 Worker가 비공개 조사 데이터도 소유하므로 관리자 응답의 캐시·검색 노출을 막고 향후 역할 확장 시 별도 인증 체계를 재검토해야 한다.

## 영향과 검증

- 영향: `src/radar-*`, `src/worker.mjs`, `site/admin/radar`, `migrations/0002_opportunity_radar.sql`, 환경 문서와 회귀 매니페스트
- 검증: `npm run verify`, 관리자 API 단위 테스트, 생성된 `/admin/radar/` 정적 검사
