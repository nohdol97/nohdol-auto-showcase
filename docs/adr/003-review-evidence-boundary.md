# ADR 003: 출처 역할을 검증하는 당근 후기 분석 경계

- 날짜: 2026-09-06
- 상태: accepted
- 부분 대체: ADR 001의 후기 전면 제외 경계. 인증·소유권·자동 연락 금지는 유지.

## 배경

사용자가 제공한 당근 업체 페이지를 일반 HTTP 요청으로 읽을 수 있었다. 그러나 JSON-LD의 후기 본문에 사장님 답글이 포함돼 있었으며, 초기 HTML의 업체 데이터는 고객 content와 comment.content를 구분했다. 타입 이름만 믿으면 고객 경험과 업체 응답을 뒤섞거나 중복 집계한다.

## 결정

로그인 없는 당근 업체 링크를 입력하는 수동 실행을 기존 Radar Queue에 추가한다. 알려진 초기 HTML 데이터 구조에서 역할을 구분하고 원문은 소비자 메모리와 `store: false` 모델 입력에서만 사용한다. 저장하는 것은 근거 요약·프로그램 가설·검증 질문과 수집 메타데이터다. 출처 식별자는 기존 TEXT 열에 `daangn:<id>`로 분리하며 새 마이그레이션은 하지 않는다.

Google Places의 저장·표시 조건과 실제 연결은 아직 검증되지 않았으므로 이 구현의 수집원에 포함하지 않는다. 기존 Kakao 주변 업체 검색과 웹 근거 분석은 계속 사용할 수 있다.

## 대안과 결과

- JSON-LD 범용 Review 파서: 관찰한 역할 오표기로 제외.
- 모델에게 검색·후기 수집을 모두 위임: 실제 읽은 본문과 근거 참조를 독립 검증하기 어려워 제외.
- 전체 후기 저장/페이지 순회: 필요한 검증 범위보다 넓어 제외.
- 장점: 링크 하나로 재현 가능하며 신호와 가설이 추적된다. 외부 원문은 장기 저장하지 않는다.
- 비용: 당근 초기 데이터 구조가 바뀌면 명시적으로 실패한다. 일부 후기만 읽으므로 전체 고객 의견이나 시장 수요를 대표하지 않는다. 레거시 열 이름은 후속 데이터 모델 변경 때 정리할 수 있다.

## 검증

스펙 004의 합성 fixture, 출처 역할·URL·Queue·모델 참조 회귀, 전체 검증과 관리자 화면 검증으로 확인한다. 운영 배포와 실제 모델 품질은 별도 증거다.
